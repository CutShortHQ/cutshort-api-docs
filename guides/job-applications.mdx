title: Job applications
description: Pipeline stages and relevance-sorted applications for a job

Use these endpoints to work with **candidates who applied to your jobs** — as opposed to [Search candidates](/guides/search-candidates), which searches the open talent database.

**Eval keys** (`applications:read`, `jobs:read`) can list jobs and stages, list applications (default stage), and fetch application detail with resume text and [profile signals](/guides/profile-signals) **without unlock**. Contact info still requires unlock — see [Get candidate details](/guides/get-candidate-details).

## Typical flow

1. **`GET /jobs`** — list workspace jobs and pick a `jobId` *(eval or production — `jobs:read`)*
2. **`GET /jobs/{jobId}/stages`** — list pipeline stages and get each `stageId` *(eval or production — `jobs:read`)*
3. **`GET /jobs/{jobId}/applications`** — list candidates in a stage *(eval or production — `applications:read`)*
4. **`GET /applications/{applicationId}`** — full triage for one applicant *(eval or production)*
5. **Unlock** *(optional, production)* — email/phone when needed

You need a **`jobId`** from `GET /jobs`, `POST /jobs`, or the Cutshort UI.

## GET /jobs/{jobId}/stages

```
GET /api/v1/jobs/{jobId}/stages
```

Returns all pipeline stages for the job, sorted by `order`.

**Scope:** `jobs:read` (included on **eval keys**)

**Rate limit:** global only (120 req / 60s)

### Response

```json
{
  "results": [
    {
      "stageId": "abc123",
      "title": "Applications",
      "type": "candidates",
      "order": 0,
      "stagePurpose": "applications_received",
      "applicationCount": 847,
      "automations": [
        { "type": "send_message", "summary": "Sends an automated message to the candidate" }
      ]
    },
    {
      "stageId": "def456",
      "title": "Shortlisted",
      "type": "connected",
      "order": 1,
      "applicationCount": 42,
      "automations": []
    }
  ]
}
```

| Field | Description |
| --- | --- |
| `stageId` | Pass to `GET .../applications?stageId=` to list that stage |
| `type` | Stage kind — `candidates` is the default **Applications** stage (incoming applications) |
| `title` | Display name in the Cutshort UI |
| `order` | Pipeline position (0 = first) |
| `applicationCount` | Active applications currently in this stage |
| `automations` | Summary of automations that fire when a candidate enters this stage |

<Note>
  Stage `type: "candidates"` is the **Applications** stage — the default when you omit `stageId` on the applications list endpoint.
</Note>

### Example

```bash
curl -s "https://cutshort.io/api/v1/jobs/JOB_ID/stages" \
  -H "Authorization: Bearer cs_live_YOUR_KEY"
```

## GET /jobs/{jobId}/applications

```
GET /api/v1/jobs/{jobId}/applications?sort=relevance&page=1&pageSize=10
```

Lists applications for a job in a given pipeline stage.

**Scope:** `applications:read` (included on **eval keys**)

**Rate limit:** global only (120 req / 60s)

### Query parameters

| Param | Default | Description |
| --- | --- | --- |
| `stageId` | Applications stage (`type: "candidates"`) | Filter to a specific stage — use `stageId` from `GET .../stages` |
| `sort` | `relevance` | `relevance` (AI shortlisting score, highest first) or `recency` (newest in stage first) |
| `includeNotAFit` | `false` | When `true`, include AI-reviewer **not a fit** applications (excluded by default) |
| `page` | `1` | Page number |
| `pageSize` | `10` | Results per page (max **20**) |

### Default behaviour

With no `stageId`:

- Returns applications in the job's **Applications** stage (`type: "candidates"`)
- Sorted by **`relevance`** (`shortlistingCriteriaScore` descending)
- Excludes AI-flagged **not a fit** candidates (unless `includeNotAFit=true`)

To list **Shortlisted**, **Rejected**, or other stages, pass the `stageId` from [GET /jobs/{jobId}/stages](#get-jobsjobidstages).

### Response

Each row includes application metadata and a **triage-only** nested `candidate` object (`lockStatus`, `displayName`, `headline` — email/phone only when already unlocked). For resume text, `profileSignals`, and screening Q&A, call [GET /applications/{applicationId}](#get-applicationsapplicationid).

```json
{
  "results": [
    {
      "applicationId": "app_001",
      "jobId": "JOB_ID",
      "stageId": "abc123",
      "stageType": "candidates",
      "threadId": "thread_789",
      "talentCardId": "64f1a2b3…",
      "addedToCurrentStageOn": "2026-07-20T10:30:00.000Z",
      "lastActivityOn": "2026-07-22T14:00:00.000Z",
      "relevance": {
        "shortlistingCriteriaScore": 0.92,
        "fitment": "good_fit",
        "fitmentReason": "Strong Python backend experience matches must-haves."
      },
      "candidate": {
        "talentCardId": "64f1a2b3…",
        "lockStatus": "locked",
        "displayName": "Priy-42",
        "headline": "Senior Backend Engineer · Python",
        "email": null,
        "phone": null
      }
    }
  ],
  "page": 1,
  "pageSize": 10,
  "totalCount": 847,
  "totalPages": 85
}
```

| Field | Description |
| --- | --- |
| `relevance.shortlistingCriteriaScore` | AI relevance score — higher = better match for the job |
| `relevance.fitment` | AI fitment label (e.g. `good_fit`, `not_a_fit`) |
| `relevance.fitmentReason` | Human-readable explanation from the AI reviewer |
| `threadId` | Conversation thread — for messaging integrations |
| `totalCountIsCapped` | Present when a stage has more than 1000 applications — `totalCount` then reflects only the first 1000 fetched |

### Example — default Applications stage

```bash
curl -s -G "https://cutshort.io/api/v1/jobs/JOB_ID/applications" \
  -H "Authorization: Bearer cs_live_YOUR_KEY" \
  --data-urlencode "sort=relevance" \
  --data-urlencode "page=1" \
  --data-urlencode "pageSize=20"
```

### Example — Shortlisted stage

```bash
curl -s -G "https://cutshort.io/api/v1/jobs/JOB_ID/applications" \
  -H "Authorization: Bearer cs_live_YOUR_KEY" \
  --data-urlencode "stageId=STAGE_ID_FROM_STAGES_ENDPOINT" \
  --data-urlencode "sort=recency"
```

## GET /applications/{applicationId}

```
GET /api/v1/applications/{applicationId}?resumeVersion=summary
```

Returns full detail for one application: `relevance`, top-level **`profileSignals`**, and a nested `candidate` with resume text and profile.

**Scope:** `applications:read` (eval keys OK)

**Rate limit:** global + sensitiveRead (30 + 120 req / 60s)

| Param | Default | Description |
| --- | --- | --- |
| `resumeVersion` | `summary` | `summary` or `full` resume text in `candidate.profile` |

| Lock state | What you get |
| --- | --- |
| **locked** | `redactedResumeText`, redacted `profile`, `profileSignals` — **no resume files** |
| **unlocked** | Full identity, `originalResumeDownloadUrl`, full `profile`, `screeningQuestions` for this job |

Use `applicationId` from the list endpoint. See [Profile signals](/guides/profile-signals) to interpret `profileSignals`.

```bash
curl -s "https://cutshort.io/api/v1/applications/APP_ID?resumeVersion=summary" \
  -H "Authorization: Bearer cs_live_YOUR_KEY"
```

## Applications vs talent search

| | **Job applications** | **Talent search** |
| --- | --- | --- |
| Endpoints | `/jobs/.../applications`, `/applications/...` | `/search/candidates` |
| Who | Candidates who **applied** to your job | Open **talent database** |
| Eval key | Yes — list + detail without unlock | Yes — search only |
| Default sort | Relevance (AI score) | AI or structured search |
| Contact info | Unlock when needed | Unlock when needed |
